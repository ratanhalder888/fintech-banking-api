# AGENTS.md

## Architecture Reality
- Django 6.0.3 + DRF 3.17.1 + Python 3.12.
- Apps in `core_apps/`: `common` (shared models, `CookieAuthentication`, renderers), `user_auth` (custom User, OTP login, lockout), `user_profile` (Profile + NextOfKin), `accounts` (BankAccount, Transaction, deposit, verification).
- Wired routes:
  - `/api/v1/auth/` — Djoser endpoints plus custom `login/`, `verify-otp/`, `refresh/`, `logout/`.
  - `/api/v1/profiles/` — profile list/detail and next-of-kin.
  - `/api/v1/accounts/` — `verify/<uuid>` and `deposit/`.
  - `/api/v1/schema/` — OpenAPI schema + Swagger/ReDoc.
- `config/settings/production.py` is empty; `config/settings/test.py` is used by the test runner.
- `manage.py` defaults to `DJANGO_SETTINGS_MODULE=config.settings.local`.

## Auth Flow
- OTP-based login: `POST /api/v1/auth/login/` → email OTP → `POST /api/v1/auth/verify-otp/` → returns JWT and sets `access`/`refresh` HTTP-only cookies.
- Default DRF auth class is `core_apps.common.cookie_auth.CookieAuthentication`: `Authorization: Bearer <token>` header wins; `access` cookie is fallback.
- Custom User: `AUTH_USER_MODEL="user_auth.User"`, `USERNAME_FIELD="email"`, BigInteger PK generated by `generate_user_id()`.
- Lockout: `LOGIN_ATTEMPTS=3`, `LOCKOUT_DURATION=1 minute` in `config/settings/local.py`.
- JWT signing requires `SIGNING_KEY` env var.
- `ADMIN_URL` is configurable via env; do not assume `/admin/`.

## Environment & Settings
- Copy `.envs/.env.example` → `.envs/.env.local` and fill values.
- Env is loaded twice from `.envs/.env.local`: once in `base.py` and again in `local.py`. Harmless.
- `DEBUG` is read as a raw string (`"True"`/`"False"`), not a boolean.
- PostgreSQL only; SQLite block in `base.py` is commented out. `config/settings/test.py` switches to SQLite in-memory.
- `local.py` hardcodes `EMAIL_HOST="mailpit"`, `EMAIL_PORT=1025` for Docker dev, overriding env values.
- `ALLOWED_HOSTS`: `localhost`, `127.0.0.1`, `0.0.0.0`. `CSRF_TRUSTED_ORIGINS`: `http://localhost:8080`, `http://127.0.0.1:8080`.
- Required env vars include: `SECRET_KEY`, `DEBUG`, `SITE_NAME`, `ADMIN_URL`, `DOMAIN`, `EMAIL_HOST`, `EMAIL_PORT`, `DEFAULT_FROM_EMAIL`, `POSTGRES_*`, `SIGNING_KEY`, plus `BANK_NAME`, `CELERY_FLOWER_*`, `CELERY_BROKER_URL`, `CELERY_RESULT_BACKEND`, `CLOUDINARY_*`, `BANK_CODE`, `CURRENCY_CODE_*`.

## Dependencies
- Two dependency paths: `Pipfile`/`Pipfile.lock` and `requirements/*.txt` (kept in sync).
- Install locally: `pip install -r requirements/local.txt`.
- Docker build uses `requirements/local.txt` with `BUILD_ENVIRONMENT=local`.
- `pytest` and `pytest-django` are **not** in `requirements/` or `Pipfile`; install them manually to run tests.

## Docker
- **Prerequisite**: `docker network create banker_local_nw` (external network in `local.yml`).
- Public entrypoint is nginx at **http://localhost:8080**; port 8000 is internal only.
- Postgres is exposed at host port `5433` (not `5432`).
- Mailpit: web UI `http://localhost:8025`, SMTP `localhost:1025`.
- Flower: `http://localhost:5555`; RabbitMQ management: `http://localhost:15672`.
- Entrypoint (`docker/local/django/entrypoint.sh`) waits for Postgres; `start.sh` runs `migrate --no-input --fake-initial`, `collectstatic --no-input`, then `runserver 0.0.0.0:8000`.
- Makefile targets: `build`, `up`, `down`, `down-v`, `makemigrations`, `migrate`, `collectstatic`, `superuser`, `flush`, `banker-db`, `network-inspect`.

## Local Dev (No Docker)
- `python manage.py migrate` then `python manage.py runserver` on port 8000.
- Requires running PostgreSQL + Redis. RabbitMQ too if Celery workers run.
- If using the Docker Postgres container from the host, connect on port `5433`.

## Tests
- Tests live in `tests/` and use `config/settings/test.py` (SQLite in-memory, no external services, Celery eager).
- Run: `pytest` (or `.venv/bin/python -m pytest`).
- `pytest.ini`: `testpaths = tests`, `--nomigrations`, `--reuse-db`.
- The codebase has no linting/typechecking configuration.

## Photo Uploads (Non-obvious)
- Profile photos (`photo`, `id_photo`, `signature_photo`) are `CloudinaryField`s.
- Upload flow: serializer writes incoming photos to `temp/{profile_id}/`, then fires `upload_photos_to_cloudinary` Celery task via `on_commit`.
- Task uploads each file to Cloudinary, deletes temp files only after full success, and retries on `cloudinary.exceptions.Error`.
- `cleanup_stale_temp_files` task sweeps `temp/` orphans older than 24h (rollback safety net).

## Celery
- Worker runs prefork pool with OOM/leak guards in `base.py`: `MAX_TASKS_PER_CHILD=1000`, memory soft/hard limits 400/500 MB per child, `PREFETCH_MULTIPLIER=1`, `ACKS_LATE=True`, `REJECT_ON_WORKER_LOST=True`.
- Task time limits: 60s soft, 5 min hard.
- Beat scheduler is `django_celery_beat` DatabaseScheduler.

## Logging
- All stdlib logging is routed through Loguru via `logging_utils.InterceptHandler`.
- Console: INFO+. `logs/debug.log`: DEBUG+ (excludes ERROR). `logs/error.log`: ERROR+ with backtrace/diagnose.
- Rotation: 10 MB. Retention: 30 days. Configured at module level in `config/settings/base.py`.

## Gotchas
- `ADMIN_URL` must match the hardcoded nginx admin location in `docker/local/nginx/nginx.conf` (`/yBhdmPz-239gU2xKI9AWcbrfWDg`). If you change the env value, update nginx too or the admin UI will not proxy correctly.
- `make banker-db` hardcodes the Postgres user `MNQ_Ggm3T9WqEg`. If `POSTGRES_USER` differs, that target will fail; use the env value instead.
- `config/settings/local.py` relies on `timedelta` coming through the wildcard import from `base.py`. Adding explicit imports to `base.py` could break `local.py`.
- `docker/local/django/start.sh` runs migrations with `--fake-initial`. Be careful when adding real migrations; verify schema is applied.
- Docker Compose uses an external network; if the network is missing, `docker compose up` fails with a confusing error.
